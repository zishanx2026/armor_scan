# 装甲板视频视觉识别系统

基于 OpenCV 的 RoboMaster 装甲板视觉识别项目。项目使用面向对象方式组织视频读取、颜色分割、形态学处理、轮廓筛选、灯条配对与目标跟踪流程，通过 C++ 类封装将"读帧 → 二值化 → 去噪 → 找轮廓 → 筛灯条 → 配对 → 跟踪 → 可视化"的完整视觉流水线拆分为可维护的模块。

## 1. 项目简介

RoboMaster 视觉识别涉及视频读取、颜色空间分离、阈值分割、形态学去噪、轮廓提取、几何特征筛选、灯条配对与目标跟踪等多个环节，任一环节参数不当都会导致漏检或误检。本项目通过 `Video` 类封装视频生命周期，通过 `Frame` 类封装单帧图像的全部处理流程，并在主程序中串联流水线。

项目采用**单线程串行处理**，重点实践 C++ 类封装、OpenCV 图像处理、几何特征筛选、配对打分与跟踪补帧逻辑。

## 2. 核心功能

- **视频生命周期管理**：封装视频打开、逐帧读取、资源释放与窗口销毁，析构时自动释放。
- **红蓝颜色分割**：通过 B/R 通道差值提取颜色特征，并结合亮度特征（过曝灯条）提升分割鲁棒性。
- **形态学去噪**：针对红蓝灯条使用不同结构元素做膨胀与闭运算，抑制碎片噪声。
- **轮廓提取与灯条筛选**：提取外轮廓，按面积、长宽比、填充率、凸度、方向角等几何特征筛选灯条，红蓝使用不同参数。
- **灯条配对与装甲板组装**：基于高度差、间距比、倾斜度、方向一致性等约束生成候选配对，按打分贪心选择最优配对。
- **目标跟踪与补帧**：对已有跟踪目标做最近邻匹配，维护 `miss_count` 生命周期；当前帧无结果时用历史结果补帧。
- **可视化调试**：绘制灯条轮廓、装甲板矩形与中心点，并分窗口显示蓝/红掩码与叠加结果。

## 3. 技术实现

### 3.1 Video 类：视频生命周期封装

`Video` 类集中管理 `cv::VideoCapture` 与打开状态，将视频读取与释放封装为独立接口，析构时自动调用 `close()`。

| 接口 | 职责 |
|------|------|
| `Video(path)` | 打开视频并记录状态，失败时输出错误 |
| `is_opened()` | 查询视频是否成功打开 |
| `read_frame(out)` | 读取下一帧，返回是否成功 |
| `close()` | 释放视频资源并销毁所有窗口 |

### 3.2 Frame 类：单帧处理流水线

`Frame` 类封装单帧图像从输入到可视化输出的全部处理步骤，各步骤以独立布尔接口返回成功状态，便于主程序逐步校验。

| 接口 | 职责 |
|------|------|
| `get_frame(img)` | 接收输入帧并缓存为内部第一帧 |
| `color_swap()` | B/R 通道差分 + 亮度特征，生成红蓝掩码 |
| `morph_denoise()` | 红蓝掩码分别做形态学去噪 |
| `find_contours()` | 对红蓝掩码提取外轮廓 |
| `filter_contours()` | 调用灯条筛选并更新历史缓存 |
| `pair_light()` | 配对灯条、组装装甲板并更新跟踪 |
| `check_show()` | 绘制灯条与装甲板并显示 |

内部还提供 `filter_bars()` 与 `pair_bars()` 作为筛选与配对的纯逻辑辅助函数。

### 3.3 颜色分割与亮度增强

通过 `cv::split` 分离 B/R 通道并做双向差分，分别以不同阈值二值化得到颜色掩码。同时将图像转灰度并以高阈值提取过曝区域，与颜色掩码做 `bitwise_and` 后与颜色掩码 `bitwise_or`，使过曝灯条在颜色特征不足时仍能被保留。

> **注意**：颜色阈值（蓝 50、红 90）与亮度阈值（200）为经验值，需根据实际光照与相机曝光调整。

### 3.4 灯条筛选

对每个轮廓计算面积、最小外接矩形、长宽比、填充率与凸度，并结合长边方向角做筛选。红蓝使用不同参数：

| 特征 | 红色 | 蓝色 |
|------|------|------|
| 面积 | 30 ~ 1040 | 15 ~ 1000 |
| 长宽比 | 1.0 ~ 8.0 | 1.0 ~ 7.0 |
| 短边上限 | 15 | 20 |
| 长边范围 | 1 ~ 40 | 2 ~ 40 |
| 填充率下限 | 0.30 | 0.45 |
| 凸度下限 | 0.55 | 0.40 |
| 方向角下限 | 70° | 65° |

### 3.5 灯条配对与打分

对所有灯条按 x 坐标排序后两两组合，先做中间灯条遮挡检查与几何约束过滤，再计算综合得分：
score = 高度差比例 × 200 + (1 - 方向一致性) × 150 + 倾斜度 × 30 + 比例偏差 × 20

比例偏差取与标准装甲板比例（1.12 小装甲、1.85 大装甲）的最小距离。候选按得分升序排序后贪心选择，保证每个灯条只使用一次。

### 3.6 跟踪与补帧

对已有跟踪目标与当前帧观测做最近邻匹配（距离阈值 `MATCH_DIST`），匹配成功则更新并清零 `miss_count`，失败则累加；`miss_count` 超过 `MAX_MISS` 的目标被移除。未匹配的观测分配新 `id` 加入跟踪。当前帧无任何装甲板时，若历史结果存在且未超过补帧上限，则用历史结果补帧。

> 当前补帧逻辑与灯条缓存逻辑中的阈值（如 `m_light_bars_blue.size() < 0`）为调试遗留，实际补帧主要依赖 `pair_light()` 中的历史装甲板缓存。

### 3.7 视频路径注入与测试资源拷贝

`VIDEO_PATH` 通过 `target_compile_definitions` 在编译期注入为 `"${CMAKE_SOURCE_DIR}/video.mp4"`，`main.cpp` 直接使用该宏构造 `Video` 对象，无需在源码中硬编码路径。构建完成后通过 `POST_BUILD` 自定义命令将根目录的 `video.mp4` 拷贝到可执行文件目录：

```cmake
add_custom_command(TARGET scan POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        ${CMAKE_SOURCE_DIR}/video.mp4
        $<TARGET_FILE_DIR:scan>/video.mp4
)
```
该机制保证可执行文件旁始终有可用的测试视频，便于直接运行验证。

> **注意**：`VIDEO_PATH` 指向的是**构建机源码目录**的绝对路径，若将可执行文件拷贝到其他机器运行，需确保该路径下仍有 `video.mp4`，或修改宏定义指向部署路径。

## 4. 项目结构

```
rm-armor-detection/
├── CMakeLists.txt
├── video.mp4
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
└── lib/
    ├── CMakeLists.txt
    ├── include/
    │   ├── frame.h
    │   └── video.h
    └── src/
        ├── frame.cpp
        └── video.cpp
```

- `app/`：程序入口，串联视频读取与逐帧处理流程，逐步校验各阶段返回值。
- `lib/include/`：`Frame` 与 `Video` 类头文件。
- `lib/src/`：视频封装与单帧处理流水线实现。
- `video.mp4`：根目录测试视频，构建后自动拷贝到可执行文件目录。
- 各级 `CMakeLists.txt`：组织应用与封装库的构建。

构建目标：

- `scan_lib`：由 `lib/src/*.cpp` 构建的**静态库**（`STATIC`），通过 `PUBLIC` 向 `scan` 传递 OpenCV 头文件、链接库与 `VIDEO_PATH` 宏。
- `scan`：由 `app/main.cpp` 构建的可执行程序，链接 `scan_lib`；构建后自动拷贝 `video.mp4` 到输出目录。

## 5. 技术栈与运行环境

- 语言标准：C++17（`CMAKE_CXX_STANDARD 17` + `CMAKE_CXX_STANDARD_REQUIRED ON`）
- 构建工具：CMake 3.10+
- 图像处理与显示：OpenCV 4.x（`find_package(OpenCV REQUIRED)`）
- 开发环境：Linux

构建前需确保系统已安装兼容版本的 OpenCV 与 C++ 编译器。

## 6. 构建与运行

在项目根目录执行：

```bash
cmake -S . -B build
cmake --build build
```

根目录 `CMakeLists.txt` 设置项目元信息、C++ 标准并添加 `lib` 和 `app` 子目录；`find_package(OpenCV REQUIRED)` 在根目录执行，OpenCV 头文件与链接库由 `scan_lib` 以 `PUBLIC` 方式向下游传递。

构建完成后，`video.mp4` 会被自动拷贝到 `scan` 可执行文件所在目录。可直接运行：

```bash
./build/app/scan
```

程序启动后读取 `VIDEO_PATH` 宏指向的视频（默认为源码根目录 `video.mp4`），逐帧处理并显示三个窗口：蓝色掩码、红色掩码、叠加结果。按任意键推进，视频结束或窗口关闭后程序退出。

## 7. 项目收获

- 实践用 C++ 类封装视觉处理流水线，将复杂流程拆分为可独立校验的步骤。
- 掌握基于通道差分的颜色分割与亮度特征融合，理解过曝场景下的分割增强思路。
- 通过几何特征（面积、长宽比、填充率、凸度、方向角）组合筛选目标，积累调参经验。
- 实践候选配对 + 打分 + 贪心选择的组合优化思路。
- 理解跟踪中最近邻匹配、生命周期计数与补帧的基本机制。
- 使用 CMake 组织多目录项目，掌握 `PUBLIC` 依赖传递、`target_compile_definitions` 注入编译期常量、`POST_BUILD` 拷贝运行资源等工程技巧。

## 8. 后续改进方向

- 修复 `filter_contours()` 中 `m_light_bars_blue.size() < 0` 的无效判断，明确灯条缓存补帧策略。
- 清理 `pair_bars()` 中注释掉的重复参数块，统一红蓝配对参数来源。
- 将颜色/亮度阈值、几何筛选参数外置为配置文件，便于不同场地快速调参。
- `VIDEO_PATH` 改为运行时命令行参数或配置文件读取，避免依赖构建机绝对路径，提升可移植性。
- 将 `file(GLOB ...)` 改为显式列出源文件，避免新增文件后忘记重新 configure 导致的漏编译。
- 引入卡尔曼滤波或更稳定的跟踪器，提升高速运动下的跟踪连续性。
- 增加处理耗时统计与帧率输出，便于定位性能瓶颈。
- 将应用相关的头文件与链接配置下沉到 `app/CMakeLists.txt`，使各目标职责更清晰。
